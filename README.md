# OASIS official website

Source for **https://oasisnextbd.github.io/OASIS_official_website/** — the OASIS company site and the
**VenGuard** product site, plus the backends. The VenGuard mobile app has its own repository:
[oasisnextbd/venguard-app](https://github.com/oasisnextbd/venguard-app).

GitHub builds and publishes the site automatically from `main` (see [Publishing](#publishing)).
Nothing in this repository is generated by hand; the published files live only in the build output.

## Repository map

```
oasis-site/            OASIS company site (static)              → published at /
venguard/              VenGuard website source                  → published at /VENGuard/ (bn) and /VENGuard/en/
  site.json              settings: prices, contacts, claims, tracking, gallery
  templates/             Jinja2 page templates (Bangla + English side by side)
  assets/                CSS, JS, images, documents (published as-is)
  static/                legacy files kept at their old URLs
  assets-source/         original high-resolution renders (not published)
  tools/                 build.py (site), make_factsheet.py (PDF)
backend/
  leads-sheet/           Google Apps Script: website orders → Google Sheet, email alerts
  connected-firebase/    Firebase: device API, remote close, alerts (+ DEVICE_API.md);
                         firestore.rules also guards the team dashboard
team-dashboard/        company admin site (orders, invoices, stock, promo codes, costs) → /team/
docs/                  project documents (brand rules, developer response, setup guide)
archive/               retired files kept for reference (not published)
scripts/               build.py (assembles _site/), check_links.py
.github/workflows/     pages.yml: build, check and publish
```

## Work on it locally

```bash
pip install -r requirements.txt
python3 scripts/build.py                 # assembles everything into _site/
python3 scripts/check_links.py           # fails on any broken internal link
python3 -m http.server 8000 -d _site     # open http://localhost:8000/
```

Requirements: Python 3.10+. Node 22 only for `backend/connected-firebase`.

## Publishing

Every push to `main` runs `.github/workflows/pages.yml`: build → link check → backend unit tests → publish.
Pull requests run the same checks without publishing.
One-time setting: **Settings → Pages → Build and deployment → Source: GitHub Actions**.

## Rules every change must follow

- **Brand and coding rules:** [`docs/venguard/brand-rules.md`](docs/venguard/brand-rules.md) (palette, identity, no placeholder prices or contacts).
- **Public URLs are stable.** Pages are linked from ads, QR stickers and search results. Don't rename or move a
  published path without adding a redirect page at the old address.
- **Don't edit build output.** Change the source (`venguard/`, `oasis-site/`) and rebuild.
- **Claims rule:** product claims are switched by `venguard/site.json → claims`; only the CTO sets them to `true`.
- **Keep it bilingual:** every VenGuard string is written in both Bangla and English (`{{ t("…", "…") }}`).
- **Small, described commits;** one topic per pull request.
